# 무단횡단 방지 시스템

천안시 청소년 도시재생 챌린지(U-CAST) — AI 기반 천안시 지역현안 해결 리빙랩  
**5팀 「건영아 잘하자」 / 하드웨어형 산출물**

양쪽 인도의 **IR 브레이크빔 센서**로 보행자의 차도 진입 방향과 반대편 도착을 감지하고,
보행자가 도로를 건너는 동안 차도 LED 스트립과 `보행자 주의` 표지판을 점멸해 운전자에게
위험을 알리는 아두이노 장치입니다. 부저는 차도로 진입한 보행자에게 경고합니다.

> 이 MVP는 보행자를 횡단보도로 유도하지 않습니다. 실제로 도로를 건너는 동안
> 운전자와 보행자 양쪽에 위험을 알리는 데 집중합니다.

## 2. 문제 정의

| 항목 | 내용 |
|---|---|
| 해결하려는 문제 | 천안중앙시장 주변에서 고령 보행자가 갑자기 차도로 진입해 발생하는 무단횡단 위험을 줄인다 |
| 문제를 겪는 사람 | 천안중앙시장을 이용하는 65세 이상 고령 보행자와 주변 도로 운전자 |
| 발생 장소 | 천안 중앙시장 및 중앙동 일대(충남 천안시 동남구 사직동 290 부근) |
| 발생 상황 | 주정차 차량과 시장 출입구 사이의 사각지대에서 보행자가 갑자기 도로로 진입 |
| 운전자 측 위험 | 보행자를 늦게 발견해 급제동하거나 후속 차량과 추돌할 위험 |
| 보행자 측 위험 | 운전자에게 자신의 진입이 보이지 않는 상태에서 도로를 건넘 |
| 적용 가능 장소 | 중앙시장 주변 도로, 먹자골목 등 보행자와 차량이 혼재하는 구간 |

관련 아이디어는 이슈 #6의 “횡단보도가 아닌 구간을 건너는 보행자를 감지해 바닥 LED를 빨간색으로 점등한다”는 방향을 반영합니다.

## 3. 최종 MVP 기능

| 구분 | 내용 |
|---|---|
| 감지 | 왼쪽·오른쪽 인도에 IR 브레이크빔 센서를 1세트씩 설치해 보행자 통과를 감지 |
| 방향 판정 | 대기 상태에서 먼저 끊긴 빔을 출발 지점으로 저장해 왼쪽→오른쪽 또는 오른쪽→왼쪽 횡단을 판정 |
| 운전자 경고 | 도로 위 네오픽셀 LED 스트립 2개와 `보행자 주의` 표지판 내부 빨간 LED를 점멸 |
| 보행자 경고 | 부저가 간헐적으로 울려 차도 진입 위험을 알림 |
| 상황 종결 | 횡단 방향의 반대편 IR 빔이 끊기면 도착으로 판단하고 모든 출력 종료 |
| 수동 시연 | 빨간 버튼은 왼쪽 IR, 초록 버튼은 오른쪽 IR이 작동한 것으로 처리 |
| 안전 복귀 | 반대편 도착 신호가 없으면 설정 시간 뒤 자동으로 대기 상태 복귀 |

### 제외한 기능

- 횡단보도 방향 유도 또는 방향 계산
- 초음파센서
- 펜스와 압력센서(FSR)
- 레이저 감지선

IR 브레이크빔은 눈에 보이지 않는 적외선을 사용하므로, 감지용 가시광 레이저를 별도로 추가하지 않습니다.

## 4. 센서 배치와 양방향 알고리즘

### 센서 구성

IR 브레이크빔 **1세트**는 다음 두 부품으로 구성됩니다.

```text
IR 송신부  ───── 보이지 않는 적외선 빔 ─────  IR 수신부
                                      ↑
                                보행자가 통과
```

MVP에는 2세트를 사용합니다.

- 왼쪽 인도: 송신부 1개 + 수신부 1개
- 오른쪽 인도: 송신부 1개 + 수신부 1개
- 아두이노는 각 수신부의 `OUT`만 읽습니다.

```text
왼쪽 인도                  차도                  오른쪽 인도
[왼쪽 IR 감지선]   [도로 LED 스트립 1·2]   [오른쪽 IR 감지선]
       │                                                │
       └── 먼저 감지되면 출발                  반대편 감지 시 도착 ──┘
```

### 상태 전이

```text
[대기]
 ├─ 왼쪽 IR 또는 왼쪽 버튼  → [왼쪽→오른쪽 횡단 중]
 │                               └─ 오른쪽 IR 또는 오른쪽 버튼 → [대기]
 └─ 오른쪽 IR 또는 오른쪽 버튼 → [오른쪽→왼쪽 횡단 중]
                                 └─ 왼쪽 IR 또는 왼쪽 버튼 → [대기]
```

- 횡단 중 출발 지점의 센서가 다시 감지되면 반복 입력으로 무시합니다.
- 대기 상태에서 양쪽 센서가 동시에 감지되면 방향을 정할 수 없으므로 입력을 무시합니다.
- 반대편 감지가 너무 빨리 들어오면 `CROSSING_MIN_MS`가 지난 뒤에만 종료합니다.

> 각 LED에 저항을 사용하고, 전류가 커지면 트랜지스터 또는 MOSFET 구동 회로를 추가해야 합니다.

## 6. 핀 연결표

| 부품 | 핀 | 코드 상수 | 역할 |
|---|:--:|---|---|
| 왼쪽 IR 수신부 OUT | D2 | `PIN_IR_LEFT` | 왼쪽 인도 감지선 |
| 오른쪽 IR 수신부 OUT | D3 | `PIN_IR_RIGHT` | 오른쪽 인도 감지선 |
| LED 스트립 1 DIN | D6 | `PIN_STRIP_1` | 차도 경고 조명 1 |
| LED 스트립 2 DIN | D7 | `PIN_STRIP_2` | 차도 경고 조명 2 |
| 표지판 빨간 LED | D8 | `PIN_SIGN_LED` | `보행자 주의` 표지판 내부 점멸 |
| 수동 부저 | D9 | `PIN_BUZZER` | 보행자 경고음 |
| 빨간 버튼 | D10 | `PIN_BTN_LEFT` | 왼쪽 IR 감지 모의 |
| 초록 버튼 | D11 | `PIN_BTN_RIGHT` | 오른쪽 IR 감지 모의 |

D4와 D5는 현재 MVP에서 사용하지 않습니다.

### IR 브레이크빔 배선

제품마다 선 색과 핀 순서가 다르므로 **제품 설명의 핀 표기를 우선 확인**합니다.

- 송신부: `VCC` → 5V, `GND` → GND
- 수신부: `VCC` → 5V, `GND` → GND, `OUT` → D2 또는 D3
- 수신부가 오픈 컬렉터 출력이면 코드의 `IR_USE_INTERNAL_PULLUP = true`를 사용합니다.

### 네오픽셀 배선

- 스트립 1 `DIN` → D6
- 스트립 2 `DIN` → D7
- 각 데이터선에 330~470Ω 직렬 저항 권장
- 두 스트립 `5V` → 외부 5V 전원
- 두 스트립 `GND` → 외부 전원 GND
- 외부 전원 GND와 Arduino GND를 반드시 공통 연결

### 표지판 LED·부저·버튼

- 표지판 LED: D8 → 220~330Ω → LED `+`, LED `−` → GND
- 수동 부저: `+` → D9, `−` → GND
- 빨간 버튼: 한쪽 → D10, 반대쪽 → GND
- 초록 버튼: 한쪽 → D11, 반대쪽 → GND
- 버튼은 `INPUT_PULLUP`을 사용하므로 외부 풀업 저항이 필요하지 않습니다.

### 전원

네오픽셀은 USB 보조배터리나 정격 5V 어댑터를 사용합니다. 일반 9V 사각 건전지를
네오픽셀에 직접 연결하지 않습니다.

## 7. 코드 구조

`main.ino`는 `delay()` 없이 `millis()` 기반으로 동작합니다.

### 상태

| 상태 | 의미 |
|---|---|
| `STATE_IDLE` | 대기. 모든 출력 꺼짐 |
| `STATE_LEFT_TO_RIGHT` | 왼쪽에서 오른쪽으로 횡단 중 |
| `STATE_RIGHT_TO_LEFT` | 오른쪽에서 왼쪽으로 횡단 중 |

### 주요 함수

| 함수 | 역할 |
|---|---|
| `blockedEdge()` | IR 신호가 일정 시간 유지된 뒤 차단 상태로 바뀌는 순간만 1회 반환 |
| `buttonPressedEdge()` | 버튼 채터링을 제거하고 누르는 순간만 1회 반환 |
| `enterCrossing()` | 횡단 방향 저장, LED·표지판·부저 경고 시작 |
| `enterIdle()` | 모든 출력을 끄고 대기 상태 복귀 |
| `updateWarningLights()` | 차도 스트립과 표지판 LED를 함께 점멸 |
| `updateBuzzer()` | 부저를 간헐적으로 울림 |

### 조정값

| 상수 | 기본값 | 의미 |
|---|:--:|---|
| `STRIP1_PIXELS`, `STRIP2_PIXELS` | 10 | 실제 스트립 픽셀 수로 수정 |
| `STRIP_BRIGHTNESS` | 120 | 스트립 밝기 |
| `WARNING_LIGHT_BLINK_MS` | 300 | 도로 LED·표지판 점멸 간격 |
| `IR_ACTIVE_LOW` | `true` | 빔 차단 시 LOW인지 여부 |
| `IR_USE_INTERNAL_PULLUP` | `true` | 수신부 OUT에 내부 풀업 사용 여부 |
| `IR_CONFIRM_MS` | 80 | 신호 확정 시간 |
| `CROSSING_MIN_MS` | 800 | 도착 신호를 받을 수 있는 최소 횡단 시간 |
| `CROSSING_TIMEOUT_MS` | 60000 | 도착 신호가 없을 때 자동 복귀 시간 |
| `BUZZER_FREQ_HZ` | 2000 | 부저 음 높이 |
| `BUZZER_ON_MS`, `BUZZER_OFF_MS` | 180 / 320 | 경고음 ON/OFF 시간 |

## 8. 제작 및 시연 순서

상세 절차는 [4차시 제작 가이드](docs/assembly-guide.md)를 따릅니다.

1. 버튼 두 개만 연결해 왼쪽·오른쪽 가상 센서 입력을 확인합니다.
2. 표지판 LED와 부저를 연결합니다.
3. 네오픽셀 스트립을 하나씩 연결합니다.
4. 왼쪽·오른쪽 IR 브레이크빔 세트를 정렬합니다.
5. 왼쪽 버튼 → 오른쪽 버튼, 오른쪽 버튼 → 왼쪽 버튼 순서로 양방향 동작을 시연합니다.
6. 버튼 테스트가 끝나면 실제 빔 차단으로 동일한 상태 전이가 일어나는지 확인합니다.

### 발표 때 보여줄 핵심 장면

- 왼쪽 IR이 끊어짐 → 차도 LED·표지판·부저 작동 → 오른쪽 IR이 끊어짐 → 전체 종료
- 오른쪽 IR이 끊어짐 → 동일한 경고 작동 → 왼쪽 IR이 끊어짐 → 전체 종료
- 센서가 불안정할 때 버튼으로 같은 입력을 모의하는 비상 시연

## 9. 알려진 제약

- IR 브레이크빔 2세트만으로는 도로 중앙의 정확한 보행자 위치를 추적하지 않습니다.
- 여러 사람이 동시에 반대 방향으로 진입하면 도착과 신규 진입을 구분하지 못할 수 있습니다.
- 양쪽 빔이 동시에 끊기면 방향을 판정하지 않고 입력을 무시합니다.
- 직사광선, 송수신부 정렬 불량, 제품별 출력 논리 차이로 오작동할 수 있습니다.
- 초음파센서는 차량 접근 감지 같은 확장 기능에만 검토하며 현재 MVP에는 포함하지 않습니다.
- Tinkercad는 `Adafruit NeoPixel` 라이브러리를 그대로 지원하지 않아 실물 또는 별도 대체 스케치로 확인해야 합니다.

문제 발생 시 [문제 해결 가이드](docs/troubleshooting.md)를 확인합니다.
